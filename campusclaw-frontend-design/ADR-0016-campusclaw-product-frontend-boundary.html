ADR-0016 · CampusClaw 产品前端隔离 Runtime 调试协议

Status: Proposed · Date: 2026-08-26 · 设计文档: campusclaw-frontend · 已分析基线: bde123706305a41e51c9a47b22e6ad11bbd8204c

Context

本 ADR 最初基于 3a6358bc 的 Vue 调试页：浏览器直接调用 /campusclaw-service/v1，并把 Service URL、JWT/APPKEY、Session ID、ETag、SSE Event 和 JSON payload 作为主界面元素。当前复核基线 bde12370 已实现 Agent 工作区、对话时间线和产品化控制，但仍由浏览器直连 Runtime、在前端维护内部 Session/ETag/SSE；Thinking 仅作为 Assistant body 内的通用折叠区，Tool 卡只显示结果。Runtime 在 Assistant completed 中已保留 tool_call.arguments，但独立工具生命周期事件不携带入参，现有前端也未建立关联。用户需要在一个连续活动区中理解思考和工具调用，并看到安全入参。精确 Runtime 设计同时要求浏览器经 mate-service 访问，内部 SSE 不得字节透明转发。

Options considered

  • 继续把当前调试台扩展成产品
    Pro：改动最小，11 个接口已经接通。
    Con：内部身份、Session、ETag 和事件模型泄漏到用户边界；信息架构仍围绕接口而不是任务。Rejected。
  • 产品页面继续直连 Runtime，但隐藏高级字段
    Pro：可以快速得到更漂亮的 UI。
    Con：只隐藏视觉元素不能解决浏览器认证、授权、内部标识和 SSE 投影边界；前端仍耦合内部契约。Rejected。
  • 产品 UI 经 mate-service 公共 bridge，调试台隔离为内部诊断入口
    Pro：用户模型稳定；认证、Chat/Session 映射、错误脱敏和 Event 投影责任清晰；保留接口联调能力。
    Con：需要新增并逐项评审 Agent、Chat、Attachment、Model Catalog 和 public SSE 契约；短期不能只靠现有 11 个接口完成生产集成。Chosen。

选择理由：真实前端不是调试台的视觉换肤，而是资源边界和交互语言的产品化。bridge 缺口应显式设计，不能让浏览器为了赶进度继续依赖内部凭据与协议。

Decision

  • 生产浏览器只调用 mate-service 公共 HTTP/SSE；mate-service 终止认证、执行授权、维护公共 Chat 到内部 Session 的映射并投影安全 Event。
  • 产品主界面只展示 Agent、Chat、消息、附件、模型、深度思考、工具活动和粗粒度执行状态。
  • session_id、ETag、Runtime 凭据、原始 JSON、SSE frame 和内部错误只允许进入内部诊断入口，且生产构建默认不可达。
  • Steer、FollowUp、Abort 在产品中分别命名为“调整方向”“加入队列”“停止”。运行态 Composer 只显示当前跟进方式；desktop 默认“调整方向”，设置可改为“加入队列”，Cmd/Ctrl+Shift+Enter 对单条消息临时反转。
  • “调整方向”不宣称立即中断当前模型或工具；它在当前 Assistant Turn 与工具结束后的下一次模型调用前送达。“加入队列”只在当前执行本会自然结束时送达。
  • 工具 started/completed/result 合并为一个可展开活动卡；持久化 completed/result 替换瞬时 preview。
  • Thinking 与 Tool 按事件顺序组成 Agent 活动流；Thinking 运行时展开、完成后降权且可折叠，但始终是独立纯文本，不进入 Assistant Markdown 或 Tool viewer。
  • 前端从 Assistant completed 的 tool_call 块提取 toolCallId、名称和入参，再按 toolCallId 合并 execution 与 result；不为后到元数据新建重复卡。
  • 产品工具卡只显示 mate-service bridge 经字段策略、脱敏、资源映射和预算后的入参；禁止暴露凭据、内部 ID、绝对路径和原始未脱敏 payload。入参 viewer 不激活 Markdown、HTML 或 URL。
  • Assistant TextContent.text 原样作为 Markdown 源，通过关闭 raw HTML 的 parser、节点与 URL allowlist 以及固定 Vue 组件渲染；禁止 v-html、innerHTML、远程 Markdown 图片、相对应用路由和危险协议链接。
  • User、Thinking、Tool result 与错误不继承 Assistant Markdown 权限，分别使用纯文本或受控结构化 viewer。
  • 流式 delta、completed Entry 和 GET history 共用同一 rawMarkdown 与 renderer；未闭合尾块纯文本显示，完成态以持久化全文重新解析。
  • 断线后禁止重放副作用 POST；公共客户端重新读取持久化历史并去重。
  • Agent 目录、Chat 列表与标题、附件上传、模型友好名称和 public SSE 均标为目标态公共契约，不宣称 Runtime 已实现。
  • 产品视觉采用 Codex-inspired 中性工具工作台，保留 CampusClaw 自有品牌，不复制 OpenAI/Codex 商标。

Consequences

  • 正面：主界面围绕用户任务；内部身份与协议不越过浏览器边界；Runtime 可继续独立演进；诊断效率仍被保留。
  • 负面：需要 mate-service bridge 和多个公共资源契约；前端初期要通过 mock adapter 开发；产品事件与 Runtime 事件之间增加一层投影测试。
  • 迁移：现有页面不直接删除，先迁移到内部诊断路由或独立开发构建；产品路由完成真实集成后再决定是否移除旧入口。
  • 安全：需要构建期和 E2E 门禁，证明生产 DOM、网络日志和错误界面不包含内部凭据、Session ID、ETag 或原始 SSE。
  • 富文本安全：需要 XSS corpus、危险 URL、远程图片、超深嵌套、超预算输入和流式分块测试；失败时回退为转义纯文本并保留复制原文。
  • 活动数据安全：公共事件投影需要入参脱敏、资源映射、结构预算与投影失败测试；前端不得在公共投影缺失时回退显示内部原始入参。
  • 回滚：可以回滚产品路由和 bridge，但不能把调试台重新定义为已满足生产安全边界。
