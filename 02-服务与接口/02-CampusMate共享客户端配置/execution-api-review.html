业务问题与边界 · 调用边界

序号规则
1每天08:00汇总园区告警时，Claw需要知道当前Agent可以调用哪些接口，以及该次业务调用可使用哪份凭据。Mate拥有接口定义、授权和凭据保管；Claw消费可信结果，不保存浏览器登录Token，也不根据prompt猜测调用地址或执行身份。Schedule继续只接受credentialIds，服务身份或用户委托的具体来源由Mate权威配置解析，不把二者的选择藏在Claw的默认账号中。
2正常流程为：保存配置时核验可用Agent与凭据引用 → 到期后重新取得当前授权上下文并准备Agent → 接受新Session及根执行 → 模型选定工具后完成可信目标解析、参数校验和权限判断 → 从Mate解析该目标凭据 → 通过既有Mate execute执行 → 保存安全结果。凭据解析失败时不发业务请求，记录本次失败；实际execute结果未知时不自动再次发送。
3接口发现、服务间认证、业务执行凭据是三个边界。发现请求可使用部署层服务身份，但不得复制用户或业务执行的凭据快照。Mate校验请求来自获准Claw服务，并验证其代表的管理/执行范围；authorizationRef只是指向权威授权记录的不可猜测标识，不是持有即授权的Token。公司服务认证SDK及可信操作者传递方式尚未核验，不能以任意JSON中的tenant/owner或自定义Header代替该接线。

4expiresAt表示本次授权凭据快照的使用截止时间，不要求底层静态APPKEY采用同一失效时间；Mate应给出有限有效期，Claw过期后不得继续使用该快照。

7凭据类型超出当前Header适配能力时明确拒绝，不因接口返回任意键就支持环境变量、Shell秘密或任意外部地址注入。credentialIds为空时不调用resolve；具体无凭据工具是否可执行由Mate判断，Claw不假造secret。
