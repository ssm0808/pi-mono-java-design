mate-service Chat Command API 评审页

默认内容用于产品、前端和后端澄清业务行为；这里展示 GET 清单与命令选项；公共认证、bridge 和错误映射仍待评审，不代表接口已发布。精确 HTTP、JSON 位于折叠区。

1. 先看触发场景确认用户什么时候会调用这个接口。
2. 再看界面结果确认前端如何展示成功、不可用和失败。
3. 最后核对报文研发按需展开原始字段、Header 和响应。

查看聊天命令清单

展示当前 Chat 可发现的命令，参数控件与状态限制由前端依据命令规则和权威会话状态处理。公共路径、认证、bridge 与错误映射待评审、待实现，不得作为已发布接口的依据。

前后端怎么交互

1. 前端读取当前 Chat 命令清单按服务器顺序展示，不推测内部状态
2. mate-service在目标 bridge 中复用 Runtime 轻量投影公共认证与错误映射另行评审
3. 前端按 argumentType 选择输入：text 显示文本框，options 调用命令选项接口展示候选，省略时直接执行；argumentHint 作为占位提示命令无匹配时保留草稿，不回退普通消息；前端不按命令名写特殊逻辑

200 · 命令清单

返回该 Chat 所属 Agent 的完整命令；Mate 以 Chat 映射的 sessionId 调用 Runtime，结果与 Runtime 带 sessionId 的清单逐项相同，不随会话运行状态变化。

描述符包含 name、type、description、可选 argumentHint 与 mate-service 补充的可选 argumentType。argumentType 只由 Mate 维护的命令映射决定（name 与技能命令为 text，model、thinking、mode 为 options），不随会话状态变化；参数始终可省略；所有 Skill 允许附件，Builtin 不允许；运行中的 model/thinking/mode 只允许无参查询。

无完整 Agent 快照时，目标清单失败，不返回残缺 Builtin；公共错误映射保留待重审状态。

GET 是观察结果，不保证随后 POST 一定成功；POST 仍需独立解析并在所属事务或锁内复核。

Skill 发现不等于 Skill 执行协议已发布。旧公共 POST SSE 已废止，不属于本次 GET 恢复范围。

状态未知、恢复中或清单过期时暂停提交并读取权威状态；状态变化不能清空参数后自动改成查询。

Runtime 清单已改为按 Agent 查询；公共路径是否同步改为按 Agent 查询待定，当前保留 Chat 路径。

查看命令选项

前端选中选项型命令后，用一个通用接口取得当前值和带显示名的候选，不再按命令写查询逻辑。公共路径、认证、bridge 与错误映射待评审、待实现，不得作为已发布接口的依据。

前后端怎么交互

1. 前端选中 argumentType=options 的命令后调用本接口同一套列表展示所有选项型命令
2. mate-service按 commandName 选择选项来源，从 Runtime 读取该会话的当前值与可选值，补充模型名称或本地化显示名返回 currentValue 与 value/label 候选
3. 前端展示 label、勾选 currentValue，提交选中的 value提交仍走命令执行入口并在 Runtime 锁内最终准入

HTTP错误码发生场景

404COMMAND_OPTIONS_NOT_FOUNDcommandName 不是该 Chat 清单中 argumentType=options 的命令，包括无参命令、文本命令和技能命令。
503COMMAND_OPTIONS_UNAVAILABLE暂时无法读取会话可选值、可选模型或模型管理；UI 保留 Slash 草稿。

每个选项型命令在 mate-service 有一个选项提供者；新增选项型命令只需新增提供者并在清单映射中标为 options，前端不改。

选项是读取时的观察结果，不是执行授权；运行中仍只允许无参查询，提交以执行接口的最终准入为准。

thinking 与 mode 的可选值由 Runtime 按会话给出（ListSessionThinkingValues、ListSessionModes），mate-service 不写死取值，只补显示名；当前模型不支持深度思考时 thinking 只返回 off。

model 的候选范围只来自 Runtime 的会话可选模型，模型管理只补名称，不能增加或删除候选；某个模型在模型管理中没有名称时 label 回退为 modelId，模型管理整体不可用时返回 503。

上游依赖与提供者结构见 mate-service 聊天命令 API 设计 §3。
