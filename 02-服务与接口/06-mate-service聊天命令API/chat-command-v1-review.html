mate-service Chat Command API 评审页

默认内容用于产品、前端和后端澄清业务行为；精确 HTTP、JSON 和 SSE 报文保留在每个接口下方的折叠区。

1. 先看触发场景确认用户什么时候会调用这个接口。
2. 再看界面结果确认前端如何展示成功、不可用和失败。
3. 最后核对报文研发按需展开原始字段、Header 和事件。
业务评审视图

查看聊天命令清单

【已废止历史；不得作为实现依据】用户在聊天输入框键入 Slash 时，前端调用本接口获取当前 Chat 可以展示的命令及其实时可用状态。

前后端怎么交互

1. 用户在输入框第一个字符输入 /前端开始识别 Slash 命令
2. 前端携带 chatId 请求命令清单不接触内部 sessionId
3. mate-service校验登录用户和 Chat 权限，再解析内部 Session向 CampusClaw 查询当前命令
4. 前端展示命令、参数提示和不可用原因请求失败时保留用户草稿

Session 正在运行时，命令清单怎么读

命令用途不填参数填写参数前端展示
/help列出命令清单或查看指定命令详情可执行可填写参数正常展示
/status查看 Session 状态、模型和深度思考可执行不接受参数正常展示
/name查看或修改 Session 名称可执行可填写参数正常展示
/model查看或切换模型可执行不可填写（SESSION_BUSY）允许无参数调用，禁用参数输入
/thinking查看或切换深度思考可执行不可填写（SESSION_BUSY）允许无参数调用，禁用参数输入
/compact压缩当前上下文不可执行（SESSION_BUSY）不接受参数置灰并说明原因
/skills列出当前 Agent 绑定的 Skill可执行不接受参数正常展示
/skill:pdf分析和生成 PDF 文档不可执行（SESSION_BUSY）不可填写（SESSION_BUSY）置灰并说明原因

业务评审视图

执行聊天命令

【已废止历史；不得作为实现依据】用户确认 Slash 命令后，前端提交命令名、参数和附件；mate-service 完成权限校验和内部 Session 映射，再把安全结果流式返回。

前后端怎么交互

1. 前端提交结构化命令请求name 不带 /，保留原始参数
2. mate-service校验用户、Chat 权限和请求字段失败时直接返回稳定错误码
3. CampusClaw执行 Builtin 或带调用快照的 Skill命令接受后断线也继续执行
4. mate-service过滤内部标识并投影公共事件前端只接收可展示和可恢复的数据

前端需要提交什么

字段必填业务含义示例
name是要执行的命令名，不包含开头的 /skill:pdf
arguments否Slash 命令名后面的原始文本分析附件并总结
fileIds否用户已经上传的附件；只有 Skill 可以携带[file-...]

成功后用户会看到什么

Builtin：/name 园区网络故障分析

  1. 前端提交 name 和新的显示名称
  2. CampusClaw 更新 Session 名称
  3. mate-service 返回名称变化和命令完成事件

界面结果：聊天标题更新，并显示命令执行成功

Skill：/skill:pdf 分析附件并总结

  1. 前端提交用户要求和附件 ID
  2. 界面显示用户消息
  3. Assistant 内容逐步显示，最终结果进入历史

界面结果：用户像普通对话一样看到流式回答

失败时前端需要区分什么

HTTP错误码发生场景
400INVALID_CHAT_IDchatId 不符合公共 Chat 约束。
400INVALID_COMMAND_REQUESTJSON 非法、包含未知字段、字段越界、Builtin 携带附件或参数形状不符合命令定义。
401UNAUTHENTICATED用户未登录或访问令牌无效。
403CHAT_ACCESS_DENIED用户无权执行该 Chat 的命令。
404CHAT_NOT_FOUNDChat 不存在、已删除，或没有有效 Session 映射。
404COMMAND_NOT_FOUND命令不存在，或 Skill 在清单返回后已解绑。
409SESSION_BUSYSession 正在执行；本次修改或执行只允许 idle。
503COMMAND_UNAVAILABLERuntime 无法解析命令或建立完整 Skill 快照。
502RUNTIME_COMMAND_FAILEDCampusClaw 未接受命令，或响应无法安全映射。
200COMMAND_EXECUTION_FAILED流建立后执行失败；公共层先投影 command.failed，再发 stream.error 并关闭，不发 stream.end。

浏览器断线不会取消已经接受的 Skill 或 Compact；重新加载后查询历史，不自动重复提交命令。

mate-service Chat Command API

1.1.0Public · 已废止 · historical target-only字段：lowerCamelCaseHeader：保留原名
/mate-service/v1
POST/chats/{chatId}/command【已废止历史】执行 Builtin 或 Skill 命令并流式返回结果执行聊天命令executeChatCommand

作用

已废止的 historical target-only design；不得作为实现依据。新公共命令协议待独立评审，不能由 Runtime 1.44.0 推导。以下保留旧提案快照：交互层提交结构化 name、arguments 和 fileIds；name 不含 Slash。mate-service 验证登录用户和 Chat 权限，解析唯一 Session，并使用内部凭据调用 CampusClaw。它解析内部 SSE，删除 sessionId、entryId、Agent/Skill ID、版本、受管路径和私有快照，再生成公共事件。Service 统一处理省略字段并拒绝未知字段。Skill 或 Compact 接受后，浏览器断线不取消执行；客户端从持久化历史查询结果，不重放 POST。当前 mate-service 尚无 Chat→Runtime bridge，因此本接口是 target-only design。

参数与请求体
