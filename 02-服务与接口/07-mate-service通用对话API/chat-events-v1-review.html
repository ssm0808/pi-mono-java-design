mate-service General Chat API

0.1.0Public · 评审中 · target-only
/mate-service/v1
POST/chats/{chatId}/events提交一条普通 Chat 消息并流式返回执行事件

作用

浏览器向已有 Chat 提交 message 和 fileIds。mate-service 先验证登录用户与 Chat 权限，再通过私有 chatId 到 sessionId 映射调用 CampusClaw Runtime。它逐帧解析内部 SSE，删除内部标识、凭据、原始思考、未经脱敏的工具数据与 Runtime 错误细节，然后输出公共 SSE。请求一旦被 Runtime 接受，浏览器断线不会取消执行，也不得自动重放 POST；恢复由后续 GET Chat Events 接口承担。当前 mate-service 源码中不存在该 Chat bridge，因此本操作是 target-only design。

认证

登录用户 Bearer Token（建议）
Header必填示例值说明
Authorization是Bearer <USER_ACCESS_TOKEN>mate-service 验证登录用户并建立 Chat 权限上下文；该值不会原样转发到 CampusClaw
POST /mate-service/v1/chats/{chatId}/events
Authorization: Bearer <USER_ACCESS_TOKEN>

参数与请求体

位置名称必填约束说明
pathchatId是string, 1..128用户有权访问的公共 Chat 标识；不得提交内部 sessionId
headerAccept-Language否zh-CN | en-US流建立前 ResultBean 与流内错误消息语言；缺失或不支持时回退 en-US

message 可省略，但提供时必须非空白且最多 262144 个 UTF-16 代码单元；fileIds 可省略，最多 32 个匹配 ^file_[0-9A-Za-z]{26}$ 且互不重复的字符串，并保留顺序。message 与 fileIds 至少提供一项。拒绝未知字段，不接受 chatId、sessionId、modelId、thinking、metadata、type 或 Idempotency-Key。以 / 开头的 message 在本接口仍是普通消息，Slash 解析只属于已确认的交互层和结构化 Command API。文件归属和 READY 状态继续由 Runtime 接受消息后的附件 resolve 流程原子确认；公共层不得为了提前返回附件错误而改变已确认的 User Entry 接受顺序。

{
  "message": "分析附件中的园区告警并给出处理建议",
  "fileIds": [
    "file_01JY8X2E3R4T5Y6U7I8O9P0A1S"
  ]
}
