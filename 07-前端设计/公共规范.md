# 前端公共规范

版本：1.1.0 · 2026-10-08

[前端设计](README.md) · [场景原型](原型/index.html)

所有场景共用这些规则。产品布局、颜色、键盘、浮层与文案在本页维护；场景页只记录差异。
## 10. 视觉与组件基线

### 10.1 布局

- 设计画布：1440 × 900；桌面优先。
- 左侧导航：232 px；中屏可折叠，窄屏使用抽屉。
- 顶部栏：64 px；任务标题、智能体与状态。
- 对话正文：建议最大宽度 840 px；与 Composer 同宽，长方案沿页面滚动。
- Composer：位于应用壳底部独立布局行，最大宽度与正文一致，输入增长至 8 行后内部滚动；不覆盖时间线。

### 10.2 O1 品牌与暖中性专业配色

| Token | 建议值 | 用途 |
|---|---:|---|
| `--brand-mark` | `#D97757` | O1 品牌标识主色；不承担运行、成功或警告语义 |

| `--surface-secondary` | `#F8F3F0` | 应用壳和侧栏 |

| `--text-primary` | `#2C2724` | 正文与标题 |
| `--text-secondary` | `#6C625D` | 次要信息 |

| `--border-default` | `#DED4CF` | Composer、活动分隔线和展开详情边界 |
| `--action-primary` | `#2B2522` | 新建、发送、允许执行 |
| `--action-primary-hover` | `#463B36` | 主动作 hover |
| `--status-running` | `#00A240` | 执行中状态点和小面积进度，对应 `green-500` |
| `--status-success` | `#008635` | 已完成，对应 `green-600` |
| `--status-warning` | `#E25507` | 需要用户注意但非失败的状态 |
| `--status-danger` | `#E02E2A` | 错误、停止确认和不可逆操作 |
| `--focus-ring` | `#A9472B` | 键盘焦点与链接；不作为大面积填充色 |

工具层级和密度仍参考本机可观察的 Codex light-theme Token，但上述暖中性色与 O1 品牌色是
CampusClaw 的品牌设计，内部工作台已使用 O1 标识；这些颜色不属于 OpenAI 官方公开品牌规范。O1 原始透明 PNG 是图形
权威；CSS 不重绘、不拆分五个色块，也不对其重新着色。珊瑚色不铺满按钮、导航或消息表面，
避免与错误/警告混淆。运行中与完成都可使用绿色，但必须同时通过 spinner/进度文本和
check/“已完成”标签区分，不能只依赖颜色。

对比度核对：`#2C2724` / `#FFFCFA` 为 14.45:1，`#6C625D` / `#FFFCFA` 为 5.80:1，
`#A9472B` / `#FFFCFA` 为 5.67:1。O1 主色 `#D97757` / `#FFFCFA` 仅 3.06:1，因此只用于
非文字品牌图形；小号正文、链接或按钮文案不得直接使用该色。

### 10.3 可访问性与键盘

- 正文与交互文字至少满足 WCAG 2.2 AA；状态不能只靠颜色表达。
- 所有图标按钮具有可读名称；主要命中区至少 44 × 44 CSS px。
- 普通消息 idle 时 `Enter` 发送、`Shift+Enter` 换行；running 时保留草稿且不提交新消息。
- Slash 清单使用 listbox 键盘语义；选中只填入，第二次明确 Enter 才执行，IME composition 期间不触发选择或执行。
- Tool Activity 使用可聚焦的 disclosure；展开状态通过 `aria-expanded` 表达，详情的 DOM 顺序始终是输入在前、输出在后。
- Thinking 与 Tool 使用独立 disclosure；读屏只在分析开始、工具状态变化和分析完成时播报状态；用户可聚焦阅读原始推理全文，不逐 token 自动播报。
- 入参 viewer 用语义化 description list/tree 表达键值和层级；被脱敏、被截断和无入参都有非颜色文字状态。
- 流式文本更新使用低打扰 live region，避免每个 token 都被读屏播报。
- 富文本保留语义标题、列表、引用、表格和代码；复制按钮具有包含语言/用途的可读名称。
- `prefers-reduced-motion` 下取消 spinner 旋转，保留静态状态文本。

### 10.4 响应式

- `> 1100 px`：232 px 完整导航与对话。
- `901..1100 px`：190 px 紧凑导航，保留会话名称。
- `<= 900 px`：导航使用抽屉；Composer 模型/思考进入设置入口，模式文字保持可见。
- `<= 480 px`：审核按钮自然换行，保留方案、反馈、任务状态与发送/停止；智能体目录与诊断不做并排布局。
- 工具输入和输出在所有断点都保持纵向顺序；只允许单个参数值、表格或代码结果自身横向滚动，不把两区改成左右列。

### 10.5 滚动、浮层与会话操作

应用壳划分顶部、时间线、底部输入三行。时间线使用 `min-height: 0` 和独立纵向滚动；Composer 与任务/命令 Dock 占真实布局高度，不用绝对定位压住最后一题、操作按钮或答案。移动端按 `visualViewport` 与 safe-area 调整可用高度；Dock 收起后仍保留当前问题的可达位置。停止不遮住问答按钮。

模式、会话、搜索结果和 Slash 菜单复用 `OverlayHost`：挂载到根浮层容器（Vue Teleport），定位依据触发器矩形与当前可见视口；上下空间不足时翻转，左右钳制并保留至少 8 px 边距，内容超高只滚菜单内部。单纯增大 z-index 不能解决祖先 overflow 裁切。滚动、缩放、窗口/软键盘变化重新定位；锚点消失时关闭。浮层互斥，打开另一个菜单关闭当前菜单。

外点、Escape、焦点离开、选择操作或切换会话均关闭菜单；Escape 返回触发器，外点尊重用户点击的新焦点。菜单支持方向键、Home/End、Enter，点击菜单不触发底层会话选择。弹窗保持焦点约束，关闭后恢复到合理入口。

侧栏使用品牌、新建/搜索、可滚动列表、底部设置四段布局。搜索固定占位，输入与结果均不被列表盖住；长会话名单行截断，完整名通过可访问名称读取，时间与三点按钮各占独立宽度。列表项的操作按钮始终可用，不与时间重叠。

三点菜单固定提供“重命名”“置顶 / 取消置顶”“删除”。删除绑定被点击行的 Session ID，不要求先选中；弹出包含名称的确认框，成功后才移除索引，删除非当前会话不改变当前对话。删除当前会话后回到新会话入口，不自动创建新 Session。running 时提示先停止，在服务端仍重新检查；404 可移除失效索引，无权限/失败保留该行。不确定结果只读核对，不自动重放删除。公共删除适配未接入时显示不可用原因。

### 10.6 简洁文案

状态文案由一个共享映射维护，仅描述当前事实和必要动作，不重复生成协议通知；界面按钮统一 Build / Plan，协议值仍为 `build` / `plan`。措辞是 CampusClaw 产品决定，借鉴 Codex 的简洁风格，不宣称逐字复制其官方文案。

| 场景 | 界面文案与位置 |
|---|---|
| 普通执行 / Plan 调研 | 当前活动用“处理中” / “规划中”，没有动作时不填充协议占位消息 |
| 等待问题 / 审核 / 工具权限 | “等待回答” / “等待审核” / “等待确认”；问答已知等待不显示“后台仍在执行”或运行 spinner |
| 提交 / 停止 | “提交中” / “停止中”；这些状态不表示已接受或已终止 |
| 正常完成 | 已有最终回答则不追加“本轮已完成”；只有无最终正文时保留轻量“已完成”，读屏只播报一次 |
| 停止 / 失败 | “已停止” / “执行失败”；失败附一句可采取的动作，保留真实结果 |
| 恢复 / 不确定 | “同步中” / “连接中断，状态待确认”，动作“刷新状态”；不把未知当失败或完成 |
| 问答操作 | “上一步”“下一步”“提交回答”；已接受后“已回答”，展开查看全部答案 |
| 方案操作 | “执行计划”“修改计划”；提交的仍是精确方案审核，复制用“复制计划” |
| 设置 | “开发者设置”“保存并应用”“已保存”“未保存”；无必要时不解释 Runtime、env、Event 或根执行 |


### 10.7 简体中文术语

用户界面使用统一的简体中文名称，按钮、标签、提示、详情和读屏名称保持一致。技术文档中的类名、字段名、接口资源和原始代码保持原名，避免改变协议含义；已确认的 Build / Plan 模式按钮及品牌名继续沿用原规则。

| 技术概念 | 用户界面名称 | 使用边界 |
|---|---|---|
| Agent | 智能体 | 展示真实名称，如“园区运营智能体”；选择器标签用“智能体”，不加英文后缀 |
| Session | 会话 | 需要标识时写“会话标识”，正文说明一次运行创建一个新会话 |
| Manual / Schedule | 手动 / 计划安排 | 触发方式控件只显示中文；技术映射仍使用 schedule:null / cron |
| Run | 运行记录 | 单次请求已接受显示“运行请求已提交”，执行进展与成功/失败由会话的真实状态展示 |
| Cron | 定时规则 | 普通预设用“每天”“周一至周五”“每周”“自定义”；自定义编辑标题保留“定时规则（Cron）”，便于识别表达式语法 |
| credentialIds | 凭据 / 凭据标识 | 无选择目录而必须输入ID时明确写“凭据标识”，不把引用、解析、快照等实现细节当作用户说明 |
| metadata | 管理标签 | 技术契约仍叫metadata；界面说明分类、查找用途，名称和值的约束不得改变 |

日期说明用“接下来的 5 次运行”，时区显示名称或有效标识；默认值提示“默认北京时间（Asia/Shanghai）”。未保存时提示“保存后显示接下来的运行时间”，不对用户解释服务端权威和响应字段。错误说明当前问题和下一步，例如“暂时无法确认是否保存成功。内容已保留，请先刷新核对”，不以“已受理”或“写入派发”替代用户需要理解的状态。
