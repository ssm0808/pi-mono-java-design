# 06 · 审核与修改计划

版本：1.0.0 · 2026-09-18

[前端设计](../../README.md) · [公共规范](../../公共规范.md)

检查实施范围、步骤、验证和回退方式，再批准实施或提出修改。

**前置条件**：Plan 模式收到完整方案事件；审核关联这一份方案与原任务。

## 原型

[高保真](../../原型/index.html#scene=plan&fidelity=high) · [低保真](../../原型/index.html#scene=plan&fidelity=low)

状态入口：待审核、开始规划、调研中、恢复审核、批准后实施。高保真检查布局、视觉和可操作性；低保真突出区域、顺序与动作。切换保真度保留当前输入和交互状态。

原型覆盖：演示复制、修改意见、批准、回执、修订后新方案、实施任务和恢复。

## 交互行为

| 当前状态 | 动作 / 事件 | 用户可见反馈 | 下一状态 |
|---|---|---|---|
| 待审核 | 展开 / 复制计划 | 阅读或复制完整方案 | 待审核 |
| 待审核 | 修改计划 | 出现独立意见输入区，保留普通草稿 | 编辑反馈 |
| 编辑反馈 | 提交修改意见 | 冻结本次意见，等待接受 | 提交中 |
| 已接受修改 | 新方案到达 | 展示新方案，旧稿可回看 | 待审核 |
| 待审核 | 执行计划 | 提交针对该方案的批准决定 | 提交中 |
| 提交中 | 批准已接受 | 原任务切换 Build 继续推进 | 实施中 |

## 取舍

把完整方案、审核决定与实施任务分别保留，便于核对“批准了哪一份、实施到哪里”；阅读和复制属于独立操作。

## 验收

- 复制、折叠、取消反馈保持待审状态。
- 批准回执前锁定重复操作；批准后继续原任务。
- 修订形成新方案身份；历史恢复保留已批准事实及真实进度。
