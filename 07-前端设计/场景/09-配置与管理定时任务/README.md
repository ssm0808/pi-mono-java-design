## 用户目标与前置条件

把可复用任务保存为仅手动运行，或设置自动计划，并从每次运行的独立会话查看结果。沿用工作区已绑定且有管理权限的智能体；没有智能体目录时不伪造可选资源；表单不提供凭据选择，运行时所有定时任务统一使用 Mate 配置的同一个账号。当前原型仅展示一个固定的示例智能体，实际数据由工作区提供。页面设计增量待实现，原型不能证明生产身份、调度或接口已接通。

## 页面结构

参考 Claude Deployments 的同页分区，采用轻分隔线、左侧标题与说明、右侧控件；窄屏变为单列，底部保留明确主操作。

| 分区 | 内容与行为 |
|---|---|
| 基本信息 | 名称、可见的智能体、大幅“任务内容”纯文本输入，对应 prompt，运行时作为新会话的第一条用户消息；描述单独折叠，管理描述不进入模型输入 |
| 触发方式 | 显式“手动 / 计划安排”单选，界面不附英文模式名，不以 enabled 开关混同任务暂停状态 |
| 定时配置 | 频率、24 小时制时间、每周的星期、IANA 时区；默认 Asia/Shanghai，可编辑其他合法时区；常用预设生成 Spring 六字段 |
| Cron 编辑 | 显示当前六字段表达式并提供“编辑定时规则”；进入自定义保留原式，非零秒及复杂表达式不得在初始化时被预设覆盖 |
| 计划时间 | 未保存显示“保存后显示接下来的运行时间”；保存后显示完整响应中的最多五个 upcomingRunsAt，并注明规则时区与计划/实际区别；改动时间规则时移除旧时间，不拿旧配置冒充新草稿 |
| 高级配置 | “管理标签”按需展开，映射 metadata，沿用配置契约的键值、差量和容量限制；不新增 Environment、Budget 或附件资源 |
| 任务详情 | 明确手动/定时方式、active/paused 状态、计划时间和近期 Run；常驻“立即运行”和“编辑”，定时任务提供暂停/恢复，Run 链接至实际新会话 |

常用频率为每天、周一至周五、每周、自定义 Cron。前三种分别生成 `0 m h * * *`、`0 m h * * MON-FRI`、`0 m h * * DDD`；小时和分钟取用户时间，星期用 MON～SUN。这里只是 UI 编码方式，不增加 schedule.type；“周一至周五”不代表园区节假日历。“每分钟/每小时”未作为快捷项添加；允许频率仍由现有部署策略及服务端校验决定。

## 触发方式与接口映射

| 场景 | 提交或回显规则 |
|---|---|
| 创建 Manual | 明确提交 schedule:null；保存只创建配置，不运行 |
| 创建 Schedule | 提交 type:cron、expression、timezone；有效计划保存即自动生效，不立即运行 |
| 编辑后切换到 Manual | 显式提交 schedule:null 清除旧计划；省略 schedule 只表示保持原值，不能实现模式切换 |
| 编辑后切换到 Schedule | 提交完整规则对象；保留原 active/paused 状态，暂停任务保存后仍暂停 |
| 列表/详情回显 | schedule:null 显示“手动”；有规则显示“定时”；status 单独显示“可用 / 已暂停” |
| 立即运行 | 两种模式均调用独立 run 操作；暂停也允许手动运行；同任务的在途运行仍受后端互斥约束 |

触发方式是从 schedule 是否为 null 派生的界面模型，不增加后端 triggerType 配置字段。Run 的触发来源来自该次运行记录，不从任务当前模式反推历史；定时任务也可以产生手动 Run。

新建默认 Manual，避免未选择计划就登记自动执行。定时编辑切换 Manual 时保留本地未提交 Cron 草稿，切回恢复；真正保存 Manual 才清除服务端计划。切换前保留其他输入。编辑已保存配置从当前资源初始化，不用创建默认覆盖。任何修改规则的部分更新须显式表达新值，未改字段保持既有差量约定。

## 交互行为

| 当前状态 | 动作 / 事件 | 反馈 | 下一状态 |
|---|---|---|---|
| 新建 Manual | 选择 Schedule | 展开频率、时间、时区和表达式，保留任务内容 | 定时草稿 |
| 定时草稿 | 点击编辑定时规则 | 原表达式进入可编辑字段，保留时区 | 自定义草稿 |
| 定时草稿 | 切回 Manual | 隐藏规则区域，说明仅显式运行，保留本地规则草稿 | 手动草稿 |
| 任意草稿 | 切换高低保真 | 仅改变呈现，保留输入及提交状态 | 原状态 |
| 有效草稿 | 保存 | 只派发一次写请求；完整响应回显规则及计划时间 | 已保存详情 |
| 无效草稿 | 保存 | 展示字段错误与可聚焦摘要，展开错误所在高级区域，保留输入 | 可修改草稿 |
| 保存中 | 回执丢失 / 5xx / 损坏成功响应 | 显示结果待确认，保留草稿，不自动重发、不自动运行 | 待核对 |
| 待核对 | 只读核对 | 用实际列表/详情核对配置，已确认才恢复动作 | 已确认或继续待核对 |
| 已保存详情 | 立即运行 | 展示该次 Run 受理事实、触发来源和会话入口，不宣称业务成功 | 观察运行 |
| 已暂停定时任务 | 保存配置修改 | 保持 paused，计划时间标为规则时间 | 已暂停详情 |
| 已暂停定时任务 | 恢复 | 继续未来计划，不补跑，已受理执行独立 | 可用详情 |

创建没有请求幂等键或回执查询接口；重名列表不足以唯一证明原创建成功。核对仍不确定时保留未知状态，不根据“没找到”自动再创建。手动运行也不能用重新调用 run 代替核对原结果。规则、权限与准入以服务端为权威，浏览器不启动定时器执行业务。

## 取舍

Claude Console 实际提供 Manual / Schedule、频率预设、自定义 Cron、时区和保存前未来五次展示，2026-10-08 的观察与官方 Beta 契约见[证据](../../source-evidence.md#schedule-console-evidence)。CampusClaw 采用分区与显式模式；保留 Spring 六字段、默认上海和当前智能体；不在任务中保存凭据引用，凭据由 Mate 按智能体绑定在运行时决定。现有契约已移除独立预览，故不复制保存前权威时间预览：收益是接口与保存规则只有一个权威，代价是用户须在保存后核对时间。Schedule 创建在保存后生效，不能暗示“核对通过才启用”；需要先验证任务内容可先保存 Manual 并显式运行，配置计划后仍须检查保存结果。参考页面的 Environment、Budget、Vault、挂载文件/GitHub/Memory Store 只是对照能力，不自动扩张产品范围。

本次为页面职责与映射补齐，复用前端既有全局组件图及 M10 调度图，未变更应用、持久化或 Runtime 的依赖关系。

## 验收与原型覆盖

原型覆盖新建 Manual、Schedule、Cron 自定义、暂停中的编辑、模式切换保留草稿、六字段提示、示例保存回显、受理与暂停/恢复、结果待确认和保真度切换。所有写入均在内存模拟；时间为固定响应夹具，仅覆盖周一至周五 08:00 Asia/Shanghai 的一个样例，其他规则明确没有服务端时间样例，不在浏览器自建 Cron 解析器。固定示例时间不是当前线上计划。真实分页、删除确认、目录解析、metadata 差量和真实会话跳转未在此原型完整模拟，须按既有契约验收；不把按钮点击或布局通过当成产品完成。

实现时核验：无规则创建零 Run；切换 Manual 显式清除规则；暂停状态不被模式覆盖；复杂 Cron 初始化无损；错误/未知保留草稿且写入仅一次；修改规则时旧未来时间失效；UTC 秒级时间按已保存 IANA 时区显示；窄屏无横向溢出，键盘可操作且控件命中区域至少44px。后端 Cron/DST、并发受理、授权与生产 Mate 接入分别验收。

验证记录（2026-10-08）：5组定时DOM回归、9场景/33状态入口回归、设计链接与SVG同步及API生成检查通过；实际浏览器查看1440px配置和390px详情。全部只证明设计原型，未执行产品或服务端验收。


中文文案遵循[公共规范 §10.7](../../公共规范.md#107-简体中文术语)：名称与智能体在基本信息展示，任务指令的输入标签为“任务内容”；触发方式为“手动 / 计划安排”，计划控件为“频率”“时间”“时区”，自定义为“定时规则（Cron）”，日期区为“接下来的 5 次运行”。metadata界面写“管理标签”。单次受理的用户反馈为“运行请求已提交”，不把它当作业务成功。协议字段及本页的技术映射保持原名。
