/campusclaw-service/v1
POST/sessions/{sessionId}/events一次 POST 提交用户事件，在同一响应中接收 SSE提交事件并接收对应推送submitSessionEvent

作用

已确认合并方向：POST 同时承担事件提交和对应推送，不再提供独立 GET /events/stream；GET /events 的 ListEvents 历史查询仍保留。每次提交 user.message、user.interrupt、user.tool_confirmation 中的一条，响应为 200 text/event-stream，而不是独立 ResultBean JSON。三种用户事件均必须携带 access-token。event 包装、content[]、eventId、不公开 entryId/entrySeq/runId/executionId、Header 示例与安全边界继续有效。五个基础类型名及 S1 data-only、S2 type + phase 继续有效。已确认首个业务帧返回本次提交的完整 user.* 事件（含 eventId），仅一次；后续才推送对应的 Agent/Session 事件。这明确调整原 S3，不广播其他用户输入，也不额外包装 ResultBean。当前候选是请求范围 SSE，输出只绑定本次消息、确认续跑或中断目标，不跨后续无关执行；结束规则已确认：收到本次对应的 session.status_idle 后关闭响应，等待工具确认时也关闭；之后通过新的 user.tool_confirmation POST 接收续跑结果。等待确认不是任务成功，不相关的 Session idle 不能结束本次响应。中断推送分工已确认：原 user.message 响应继续承载原执行输出；新 user.interrupt 响应首帧返回完整中断回执，之后只等待目标实际停止的 session.status_idle，不复制正文、思考或工具输出。仍连接的两条响应接收同一条 idle，复用同一 eventId，随后各自关闭。回执表示已接受中断，idle 才表示目标实际停止。数据库中断机制已确认：接收实例在同一短事务中绑定具体内部执行、保存 user.interrupt 事件和停止请求，提交后先返回完整回执；各实例独立于模型和工具调用，批量检查本机活动执行的停止请求并执行本地取消。执行实际退出后保存唯一的对应 idle；原响应与中断响应读取同一条权威结束事件，复用 eventId 后分别关闭。中断响应仍不复制 Agent 输出。当前仅依赖数据库，不依赖粘性路由、实例间转发或 Redis；Redis 仅在后续有必要时评估为通知加速，数据库记录与检查兜底保留。单消息准入已确认：同一 Session 的 M1 未执行完成前，不接受任何调用方提交的下一条 user.message M2，也不将 M2 排队或写入已接受事件历史。接受 user.message 时，在同一数据库短事务中锁定 Session、复核 state=idle、写入消息和内部执行身份，并将 state 改为 running；提交成功后才启动执行并返回完整回执。该约束按 Session 生效，覆盖不同用户和服务实例。M1 等待工具确认、正在停止或仅响应断开时仍未完成，Session 保持 running；等待确认的 session.status_idle 只结束本次 SSE，不能据此开放下一条消息。M1 真正完成或实际停止且结束状态提交后，Session 才恢复 idle。user.interrupt 和 user.tool_confirmation 按各自控制条件接受，不受新消息的 idle 前置条件阻挡。中断查询优化已确认：同实例在停止请求提交成功后立即通知对应执行，跨实例继续批量检查，数据库轮询兜底保留；固定内部执行身份是等待结果的去重键，同一目标只查一次，再分别通知本机仍连接的响应。先登记等待再补读已提交终态，避免登记前后完成导致漏发；本地通知和补读共用每条响应的终态去重，完整回执先行，同一终态每条响应最多投递一次，慢连接互不阻塞。最后一个等待者离开只清理本机登记，不删除停止请求或终态。查询索引按实际 GaussDB 版本、执行计划与 100 并发压测选择，不预先冻结具体索引、500 毫秒周期、批次上限或工具/中断等待超时。执行标识不公开；旧停止请求不能作用于下一轮执行，回执、超时或实例失联不代表已停止。数据库字段、检查周期、并发竞态、idle reason 具体值和故障处理细节仍待评审。断线不取消已接受的执行、不自动重发 POST，通过 ListEvents 对账。未整体确认合并接口，也未修改 CampusClaw 实现或 Mate 公共契约。

参数与请求体

位置名称必填约束说明
pathsessionId是^session-[0-9a-fA-F]{32}$已经存在且未删除的内部 Session 标识；不暴露给浏览器
headerAccept-Language否zh-CN | en-US异常消息语言；缺失或不支持时回退 en-US

顶层固定只有 event；event.type 是联合类型判别字段，可选择 user.message、user.interrupt 或 user.tool_confirmation。一次请求只提交一条事件，不支持数组或批量；三种事件都会被本接口接收。null 不等价于省略。user.message 的 content 长度 1..5，最多一个 text 且必须位于第一项，最多四个不重复 file。user.interrupt 无其他业务字段。user.tool_confirmation 只在等待对应 Tool Call 确认时接受。 user.message 仅在 Session 为 idle 时接受；接受消息与改为 running 同事务，上一条消息未完成前拒绝下一条，不排队。

用户消息 · user.message

文本与附件保持调用顺序；Claw 只保存 fileId 引用。 同一 Session 的上一条用户消息未完成时，本条消息不被接受。

{
  "event": {
    "type": "user.message",
    "content": [
      {
        "type": "text",
        "text": "请结合附件中的巡检记录，梳理东区园区的异常告警，并给出处理建议。"
      },
      {
        "type": "file",
        "fileId": "7f12d8a380964fdc8518f48be1cf6a42"
      }
    ]
  }
}
中断执行 · user.interrupt

只请求终止当前内部执行；200 不表示执行已经完全退出。

{
  "event": {
    "type": "user.interrupt"
  }
}
拒绝工具调用 · user.tool_confirmation

toolCallId 原样引用等待确认的 Tool Call；denyMessage 仅在 deny 时允许。

{
  "event": {
    "type": "user.tool_confirmation",
    "toolCallId": "call_unLAR8MvFNptuiZK6K6HCy5k",
    "result": "deny",
    "denyMessage": "该操作会修改生产配置，请先给出无变更风险的处理建议。"
  }
}
