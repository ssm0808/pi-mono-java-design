作用

本接口是 Session Events v2 的写入入口。每次请求提交一条用户事件，明确支持 user.message、user.interrupt、user.tool_confirmation 三种联合类型；“一条”是请求批量边界，不是只支持 user.message。三种用户事件均必须携带 access-token，JWT 与 APPKEY 两种 Header 模式遵守同一规则；携带不代表使用，Claw 只在实际调用 Mate tool execute 时发送。X-HW-ID 已确认为用户凭据 ID，不是公司、服务或应用标识。本接口不返回 Agent 输出，也不创建或公开 executionId/runId。成功响应中的事件身份已确认为 eventId，不公开 entryId 或 entrySeq；内部持久化仍可使用 Entry 标识和序号。服务端在所属事务或 Session 锁内重新检查当前状态，再持久化用户事件并触发、终止或恢复内部执行。响应丢失不代表写入失败；当前提案不接受 Idempotency-Key，调用方应通过权威历史对账且不得盲目重放。三种事件范围、事件身份、access-token 必填规则、Header 示例值和凭据处理说明已经确认，其余字段仍是本轮候选方案。

参数与请求体

位置名称必填约束说明
pathsessionId是^session-[0-9a-fA-F]{32}$已经存在且未删除的内部 Session 标识；不暴露给浏览器
headerAccept-Language否zh-CN | en-US异常消息语言；缺失或不支持时回退 en-US

顶层固定只有 event；event.type 是联合类型判别字段，可选择 user.message、user.interrupt 或 user.tool_confirmation。一次请求只提交一条事件，不支持数组或批量；三种事件都会被本接口接收。null 不等价于省略。user.message 的 content 长度 1..5，最多一个 text 且必须位于第一项，最多四个不重复 file。user.interrupt 无其他业务字段。user.tool_confirmation 只在等待对应 Tool Call 确认时接受。

用户消息 · user.message

文本与附件保持调用顺序；Claw 只保存 fileId 引用。

{
  "event": {
    "type": "user.message",
    "content": [
      {
        "type": "text",
        "text": "请结合附件中的巡检记录，梳理东区园区的异常告警，并给出处理建议。"
      },
      {
        "type": "file",
        "fileId": "7f12d8a380964fdc8518f48be1cf6a42"
      }
    ]
  }
}
中断执行 · user.interrupt

只请求终止当前内部执行；200 不表示执行已经完全退出。

{
  "event": {
    "type": "user.interrupt"
  }
}
拒绝工具调用 · user.tool_confirmation

toolCallId 原样引用等待确认的 Tool Call；denyMessage 仅在 deny 时允许。

{
  "event": {
    "type": "user.tool_confirmation",
    "toolCallId": "call_unLAR8MvFNptuiZK6K6HCy5k",
    "result": "deny",
    "denyMessage": "该操作会修改生产配置，请先给出无变更风险的处理建议。"
  }
}
