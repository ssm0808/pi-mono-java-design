CampusClaw Session Events API

2.0.0-proposal.22Internal · 当前评审：查看对话历史 · target-only字段：lowerCamelCaseHeader：保留原名
/campusclaw-service/v1
GET/sessions/{sessionId}/events分页查询与 POST SSE 一致的完整事件查看对话历史listSessionEvents

作用

当前评审 ListEvents；这是目标设计，尚未修改 CampusClaw 实现。保留 GET 历史查询，不恢复 GET /events/stream。普通分页已确认：page 从 1 开始，按旧到新的已提交内部顺序返回；nextPage 是下一页整数或 null，不是加密游标。不再固定快照，不增加快照标识、游标密钥或过期时间。每页读取该次查询可见的当前分支完整事件，跨页保持相同 limit；同一分支和过滤条件不变且仅尾部追加时，已有记录的位置不移动，新事件可以进入后续页。分支、过滤条件或历史可见范围改变时，从 page=1 重新加载；本接口不承诺自动检测跨页变化。nextPage=null 仅表示本次查询没有下一页，不表示执行已结束或以后不会新增事件。允许 Session running 时查询，不占用消息执行准入名额。分页数量已确认：省略 limit 时返回最多 50 条，允许 1～200；result 只含 events 和 nextPage，不返回 total。普通 JSON 响应继续使用 ResultBean。L4 已确认：页码合法但超出当前记录范围时返回 200，events=[]、nextPage=null，不作为分页参数错误；此规则以 Session 存在、访问检查及查询成功为前提，不掩盖非法参数或读取失败。三类已接受的 user.* 回执与 agent.message、agent.thinking、agent.tool_call、agent.tool_result、session.status_idle 使用 POST SSE 的相同 eventId、createdAt 和业务字段；正文/思考只返回 phase=completed，不返回 delta、心跳或连接结束标记。客户端保持数组顺序，不按 createdAt 重排，不公开 entryId、entrySeq 或执行标识。候选沿用 Session thinking 开关过滤已获准公开的摘要；每页重新检查访问边界，页码不是访问凭据。中断回执只表示已接受；相同停止 idle 在历史中只出现一次。等待确认的 idle 不能解除 M1 的 running 状态；不能用某条历史 idle 判定现在可提交 M2。只读接口不要求 access-token，不创建执行凭据、不调用 Mate 工具，所有凭据都不进入历史或日志。未整体确认 ListEvents 或合并 POST；配置变更、压缩、Usage 与其他扩展事件的 v2 映射仍待补齐，不能因基础示例未列出而删除既有能力。CampusClaw 内部 sessionId 不直接暴露给浏览器，Mate 公共 API 不在本轮修改范围。

参数与请求体

位置名称必填约束说明
pathsessionId是^session-[0-9a-fA-F]{32}$已经存在且未删除的内部 Session 标识；不暴露给浏览器
querylimit否integer 1..200; default 50本页最多返回的完整事件条数，不是消息轮数；用户、工具和状态事件分别计数。默认 50、上限 200 已确认。第一页/下一页示例显式使用 2，其他场景显式使用 50。同一轮翻页保持相同 limit；改变大小时从 page=1 重新加载。
querypage否integer >= 1; default 1普通页码 1、2、3……，省略按第一页处理。有后续页时使用 nextPage，也可按规则构造页码；不是 eventId 或内部事件序号，不携带快照或加密信息。
headerAccept-Language否zh-CN | en-US异常消息语言；缺失或不支持时回退 en-US

无请求体。第一页：?page=1&limit=2；配对下一页：?page=2&limit=2。按旧到新读取，跨页保持 limit 不变。不固定快照；当前样例的两次读取之间没有新增事件。
