POST/sessions/{sessionId}/events一次 POST 提交用户事件，在同一响应中接收 SSE提交事件并接收对应推送submitSessionEvent

作用

已确认合并方向：POST 同时承担事件提交和对应推送，不再提供独立 GET /events/stream；GET /events 的 ListEvents 历史查询仍保留。每次提交 user.message、user.interrupt、user.tool_confirmation 中的一条，响应为 200 text/event-stream，而不是独立 ResultBean JSON。三种用户事件均必须携带 access-token。event 包装、content[]、eventId、不公开 entryId/entrySeq/runId/executionId、Header 示例与安全边界继续有效。五个基础类型名及 S1 data-only、S2 type + phase 继续有效。已确认首个业务帧返回本次提交的完整 user.* 事件（含 eventId），仅一次；后续才推送对应的 Agent/Session 事件。这明确调整原 S3，不广播其他用户输入，也不额外包装 ResultBean。当前候选是请求范围 SSE，输出只绑定本次消息、确认续跑或中断目标，不跨后续无关执行；结束规则已确认：收到本次对应的 session.status_idle 后关闭响应，等待工具确认时也关闭；之后通过新的 user.tool_confirmation POST 接收续跑结果。等待确认不是任务成功，不相关的 Session idle 不能结束本次响应。中断推送分工已确认：原 user.message 响应继续承载原执行输出；新 user.interrupt 响应首帧返回完整中断回执，之后只等待目标实际停止的 session.status_idle，不复制正文、思考或工具输出。仍连接的两条响应接收同一条 idle，复用同一 eventId，随后各自关闭。回执表示已接受中断，idle 才表示目标实际停止。数据库中断机制已确认：接收实例在同一短事务中绑定具体内部执行、保存 user.interrupt 事件和停止请求，提交后先返回完整回执；各实例独立于模型和工具调用，批量检查本机活动执行的停止请求并执行本地取消。执行实际退出后保存唯一的对应 idle；原响应与中断响应读取同一条权威结束事件，复用 eventId 后分别关闭。中断响应仍不复制 Agent 输出。当前仅依赖数据库，不依赖粘性路由、实例间转发或 Redis；Redis 仅在后续有必要时评估为通知加速，数据库记录与检查兜底保留。单消息准入已确认：同一 Session 的 M1 未执行完成前，不接受任何调用方提交的下一条 user.message M2，也不将 M2 排队或写入已接受事件历史。接受 user.message
