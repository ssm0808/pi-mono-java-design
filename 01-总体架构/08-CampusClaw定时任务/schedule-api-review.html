共用调用规则

序号规则
1基础路径为 /campusclaw-service/v1。资源名沿用定时任务领域的 schedules；它保存完整任务配置，不是只有一个 Cron 字符串，也不宣称兼容 Claude Deployment 报文。
2定时任务全部接口不采用 If-Match 或 Idempotency-Key，不返回配套 ETag；额外传入这两个 Header 时按普通未知 Header 忽略，不赋予并发或去重语义，也不专门因此报错。不把版本或请求键改放请求体、查询参数或其他自定义 Header；创建、读取、更新、删除，以及后续试运行、暂停、恢复和 Run 读取均沿用这一接口约束。数据库内部配置代次、Run 身份和自动触发唯一约束继续保留。同一约束适用于已有 Session 等其他 Claw 接口；现有源码迁移差距见专项证据。各操作的具体规则集中在下文。
3本切片不增加 options、Agent 目录或请求回执查询接口。调用方只提交业务输入；事务控制、当前状态校验和内部调度去重由服务端完成，网络结果不确定时的核对规则见 §5。
4身份与权限边界（当前目标）。 本文所有“当前调用者、管理范围、可见范围、功能权限”的判断均由 Mate 维护并执行。Claw 不解析或保存用户、scope、owner、operator，不以本地字段比较决定用户权限；收到 Mate 可信服务请求后校验服务来源、具体操作及目标资源，再检查自己的输入、状态和事务条件。浏览器或模型提交的 ID 不能作为授权依据，缺少有效 Mate 授权结果时拒绝。
5列表必须在分页前应用 Mate 决定的获准资源集合；Claw 仅执行技术 ID 约束查询，空集合返回空，不退化为全部。集合传递与批量查询的内部契约待实现，不能只删 WHERE scope 条件后放开全库，不能先取全库一页再过滤。403/404 等用户侧语义保持；Mate 的拒绝与不可用分别映射到既有错误，不能把服务故障伪装成空列表。
6Claw→Mate 的后台查询只携带资源、执行和不透明 authorizationRef，不传持久化的用户主体；业务凭据与服务认证分开。新 Session 在受理前由 Mate 独立登记归属，Schedule/Run 删除不删除该关联；完整规则见Mate 专项。本次不新增公共身份字段或自定义 Header。PR #332 当前尚存在本地身份链路，具体源码差距见职责核验。
7普通 JSON 成功使用 resCode/resMsg/result，包括删除成功的完整 Schedule 回执及立即运行的Run记录；Run.error描述已记录的受理结果，不把它混同于HTTP请求失败；失败仅返回 resCode/resMsg，保留真实 HTTP 状态。JSON 为 lowerCamelCase。配置响应为 Cache-Control: no-store；语言支持 zh-CN/en-US，缺省或不支持时回退 zh-CN，JSON 响应返回 Content-Language。scheduleId 由服务端生成、大小写敏感且不复用；示例中的 UUID 后缀不构成客户端可构造 ID 的许可。

计划时间与最近运行摘要 · 调用边界

序号规则
1创建、详情、更新及列表元素中的非空 schedule 包含 type、expression、有效 timezone，以及只读 lastRunAt/upcomingRunsAt。两个只读字段已纳入响应范围；以下为具体运行语义，与运行接口一起验收。
2创建取一次服务端计算时刻完成规则校验，并以已保存配置组装 upcomingRunsAt、lastRunAt:null。详情/更新在各自一致读写快照中重新计算，数组按时间推进；不持久化用于客户端重试的原成功响应。所有时刻为 UTC 秒级 Z 格式。实际受理/启动可能晚于计划时刻，跳过和失败通过 Run 记录说明，不以数组保证执行。
3lastRunAt 归属于整个任务，修改 Cron 或消息不清除历史；规则为 null 时整个 schedule 返回 null，不另造空规则对象。若之后重新配置 Cron，回显任务已有的最近自动开始时间。运行专题规定从关联根执行权威结果投影实际开始时间及摘要；字段存在不等于该链路已经实现。Claude 同字段说明同时提到实际开始与“Null until one completes”，本产品明确采用实际开始语义，不据文档推断其内部写入点。
4创建与更新复用同一时间策略完成规则校验和计划计算；无未来匹配的 Cron 返回 SCHEDULE_RULE_INVALID，失败不改动已保存资源。调用方保存成功后从完整 Schedule 响应查看未来计划时间，读取时按当前配置重新计算；不提供未保存规则的独立时间预览。频率与配额由部署策略约束；超过范围返回稳定的策略错误，策略本身未配置则服务不可用。DST 与解析库版本边界必须验收，本接口不复制 Claude 的 jitter 承诺。动态摘要仅用于读取展示，不作为客户端更新前置条件。

metadata 的用途与范围 · 调用边界

序号规则
1metadata 是可选的业务关联信息，例如 { "parkCode": "park-east", "purpose": "alarm-summary" }。支持该字段，沿用 Claude 的字符串 map 与 16/64/512 限制，长度沿用本项目 Java 字符计数，不声称补充 Unicode 字符与 Claude 的计数完全一致。键必须非空，值允许空字符串；创建及保存值拒绝 null、数值、布尔值、数组和嵌套对象，不自动转换成字符串。
2创建省略返回 {}。更新沿用 Claude 的逐 key patch：字符串新增或覆盖，key 的值为 null 时删除该 key，省略 key 保留；{} 不做修改，需清空时逐 key 删除。合并后的存储对象仍满足 16/64/512 限制且不含 null；顶层 metadata:null 拒绝。metadata 不进入 user.message、系统提示或工具参数，也不自动继承为 Session 元数据；不得用其中的 tenantId、owner 或凭据引用代替可信授权。不得保存 Token、密码或其他 secret，敏感凭据应采用独立保管与授权引用。首版不承诺按 metadata 过滤或索引。

Run 查询与删除后的历史（待实现） · 调用边界

序号规则
1运营人员删除“工作日园区告警汇总”后，任务配置和该任务的运行记录一起删除；已经生成的Session及其消息、工具结果继续由会话模块管理。用户可以从对话入口查看或独立删除这些Session，不需要为了保留对话而继续保留定时配置或Run。此关系是已确认目标，新增接口和持久化接线待实现。
2正常删除与失败处理。 删除成功仍为200和ResultBean包装的完整Schedule回执，不增加Run列表、Session列表、deleted字段或cascade参数。服务提交同一删除边界，使Schedule及其Run同时退出公开读取；失败不能出现对外已删配置却仍可查Run的部分结果。物理清理是否在同一事务完成、是否需要内部清理任务属于实施方案，不能借在途协调永久保存整份配置或已删Run。Mate 为已存在的 Session 独立维护归属并执行当前权限检查，不能在删除时失去授权依据，也不能仅凭旧scheduleId/runId放行。
3删除提交前已经读取或成功受理的请求，可能在提交后才把原快照送到客户端；这不代表资源重新存在。后续新读必须遵守删除结果。Run的404或空列表也不能证明之前没有创建Session、没有发生业务执行或可以安全重发run请求。
4在途与清理约束。 删除生效后不能再受理新的Session或追加配置中的初始消息。已经受理的Session独立保留，其完成事件继续按Runtime规则保存；异步回调、失败记录与对账不得重新插入已删除Run、恢复Schedule或安装下一次计划。暂时留下的协调信息只服务于原执行收尾，不进入Run列表/详情；最小存储和清理边界见执行设计，不以删除请求触发取消。不能用数据库外键级联把Run引用的Session一起删除。
5Run与Session反向删除不对称。 单独删除Session保留仍存续任务的Run及原sessionId，不把过去的受理成功改成失败，不清空历史关联。Run读取不要求关联Session当前仍可读取；读取或删除Session始终执行其独立权限检查，404不能证明业务从未执行。
6两个读取接口。 两者均不接收请求体，使用 §2 的认证、语言及两字段HTTP错误包装，成功为200/ResultBean、Cache-Control:no-store。列表跨任务读取当前有权查看的Run；权限及删除过滤先于分页，不能以scheduleId或sessionId自行授权。
7重复标量、未知参数、非法ID、非空正文或错误类型返回400/SCHEDULE_REQUEST_INVALID；详情不接受业务查询参数。列表按createdAt DESC,id DESC排序，在同一一致性边界过滤并读取limit+1条，额外一条仅判断nextPage；有后续时为page+1，否则null。空页或超末页均为200、runs:[]、nextPage:null。普通OFFSET翻页会因新记录、删除或保留期清理出现重复/遗漏；筛选变化时从page1重读，不能用于可靠增量同步或证明某次运行未发生。
8每项沿用type、id、scheduleId、agentId、triggerContext、sessionId、error、createdAt八字段，不增加status或业务执行结果。手动来源为{type:"manual"}；自动来源为{type:"schedule",scheduledAt:"2026-10-05T00:00:00Z"}，scheduledAt是原计划时刻，createdAt是记录创建时间，均为UTC秒级。自动忙跳过以schedule_busy_error记录；停机时未观察到的计划不逐次补造Run。受理结果已确定的Run才公开，sessionId/error恰好一个非空；内部PREPARING及受理结果未知不进入公共模型。受理成功后业务失联、失败、交互被阻止或Session删除均不改写原受理事实，真实执行结果由Session/根执行管理。
9其余错误文案沿 §6/§4.10 的同名错误；成功与错误均返回实际Content-Language。查询不prepare、resolve secret、启动或取消Session，不修改Schedule/Run。记录与所属Schedule的存续、可见范围在同一一致性边界检查，避免先查配置后暴露残留Run。
10设计理由与代价。 删除后不维护该任务的运行历史入口，避免用户再单独清理Run；已生成的对话和园区业务结果独立保留。代价是无法再从Run查询启动失败、触发来源和关联记录，尤其是没有Session的失败记录；不把保留Session说成能还原完整运行历史。普通独立审计如有保留要求由所属策略明确，不能变成隐藏的Run恢复接口，也不新增整份配置备份。删除不吊销共用凭据、不删除Agent或会话附件，不撤销已经创建的工单或告警处置结果。
11沿用当日已核验的基线证据：DSH删除任务及投递历史、保留原Session，为生命周期取舍提供参照；它的投递回执不同于Claw的新Session受理Run。OpenClaw保留Run历史且操作者删除请求取消，说明历史保留与在途取消各自独立。Claude仍为公共API主基线，其公开归档资料未明确相关级联规则；Claw采用直接删除并连带删除Run属于自身产品约束，不宣称与Claude内部实现一致。
