已确认：产品前端不持有 JWT/APPKEY

credentialBoundary

当前实现没有凭据表单、秘密 VITE_* 配置、浏览器 credential store 或 Authorization / X-HW-APPKEY 注入路径；统一请求只发送非秘密 X-HW-ID。本轮只为隔离的内部开发构建增加临时 Header，不改变生产产品边界。

边界设计结论
当前内部调试链路当前仍无凭据控件；目标诊断抽屉只用于 Runtime 透传调试，不建立生产身份。
未来生产链路统一登录、mate-service 或网关负责身份与授权；具体浏览器会话机制待公共 API 评审。
诊断例外只在页面内存中接受用户填写的 Key/Value Header，仅附加到提交消息 POST；刷新或关闭页签清除。
401/403交给统一登录/权限流程，不弹出凭据框，也不自动重放副作用请求。

本轮确认项

1. 是否确认三状态信息架构？

firstUse、idleConversation、runningConversation 作为首版稳定评审和测试边界。

2. 已确认：O1 品牌标识；暖中性配色进入评审

O1 使用原始透明 PNG，不生成式重绘，也不缩进深色品牌方块；暖白、暖灰与深暖黑构成工作台，珊瑚色仅用于品牌标识，绿色继续表达运行与完成。

3. 已确认：跟进交互与 Codex desktop 一致

desktop 默认“调整方向”，设置可切换“加入队列”；Cmd/Ctrl+Shift+Enter 对单条消息临时反转。“调整方向”不会硬中断当前模型或工具。

4. 已确认：产品前端不持有 JWT/APPKEY

生产身份与授权仍由统一登录、mate-service 或网关承担；产品 Chat 不出现凭据表单、秘密构建配置或浏览器持久化。

5. 评审中：隔离的 debugHeaders 诊断能力

采用通用 Key/Value 表格、逐行启停、自动空白行和折叠的自动 Header；值只在页面内存中存活，仅附加到初始 POST /events。

6. 是否确认 Assistant-only 安全富文本边界？

Assistant 正文支持受限 Markdown；User、Thinking 和 Tool 原始结果保持纯文本/专用 viewer。raw HTML、远程 Markdown 图片、相对路由和危险协议永不激活。

7. 本轮方向：采用 Codex-inspired 活动 disclosure

Thinking 只展示公共 bridge 生成的安全标题和摘要；工具以紧凑动作行出现，当前项展开、完成项折叠，详情按“输入参数 → 输出结果”纵向排列。原始推理、内部 ID、绝对路径和凭据都不进入产品浏览器。
